# Screenshot-only versus spatial context

The comparison asset at `submission/screenshots/context-comparison.png` explains the product's WebMCP leverage with one fixed question:

> Lift 1 is closed. Find a trustworthy accessible route from Entrance A to Platform 2.

| Decision input | Screenshot-only view | Semantic spatial interface |
|---|---|---|
| Identity | Shapes inferred again from one frame | Stable entity and region IDs |
| Hidden context | Off-camera spaces and connectivity absent | Room hierarchy and route graph queryable |
| Operational state | A lift may look unchanged | Reversible `operational: closed` state is explicit |
| Trust | Confidence inferred from appearance | West corridor reports 56% accessible-wayfinding readiness |
| Recovery | No structured next step | Two concrete recapture views and undo |

The left panel is a conceptual limitation diagram, not a model benchmark. The right-panel values are receipts from the deterministic fixture and Chrome WebMCP verification. No model-backed selection result is claimed.
